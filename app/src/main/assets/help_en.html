OplusRefreshRate for PJA110 (OnePlus Ace 2 Pro) — app edition

What this app does

This app takes over panel refresh rate scheduling and the IRIS display chip (PixelWorks) display enhancements. It has three parts:

  • Refresh rate scheduling: smart mode makes decisions by scene voting (games 120Hz, downgrade after 3s idle, touch speed-up), or lock 60/90/120Hz globally.
  • MEMC frame insertion (IRIS chip): sends frame insertion / super resolution / SDR2HDR parameters per app. Entry/exit follows the ColorOS sequence (clear → ABYP → lock 120Hz → switch to PT → write params); on screen-off or exit it always falls back to ABYP bypass to prevent the freeze-causing mode-switch storm.
  • Per-app behavior: set refresh rate mode and MEMC behavior per app. User rules have the highest priority.

Quick start

  1. Open "Refresh rate mode" and pick Smart or a locked level.
  2. For MEMC: enable the "MEMC frame insertion" master switch (off by default), then either pick "Force on" for your target app under "Per-app behavior", or add its package name to the config file.
  3. Verify: adb logcat -s ORR/Iris ORR/IrisExec ORR/PerApp ORR/Service ORR/Scene

iris command format

Each command maps to one irisConfig invocation, space-separated parameters:

irisConfig <Type> <Param0> <Param1> ...

Each string in the JSON config is one command (without the irisConfig prefix), e.g. "258 3 10 0 1". Unfilled parameter slots default to 0. Commands for an app are sent in order.

Type 56 — chip mode switch (ABP bypass)

Controls the display chip's working mode; the core of the whole safety model. Managed automatically — do not send it casually in custom configs.

ValueMeaning
0Exit ABP; chip enters PT (Pass-Through) working mode — required for MEMC/SR to take effect
1Enter ABP (Analog Bypass); chip does not process the image
16Standby ABP
32Sleep ABP — default safe state when the system is idle

Read current state with irisConfig -getfeature 56 (note: -get 56 segfaults, don't use it). Read-only sysfs mirror: /sys/kernel/iris/display_mode.

Type 258 — MEMC / HDR master switch

Master control of frame insertion and HDR. Video uses the 3-param form, games the 6-param form.

SlotValuesMeaning
Param 0
Mode		 0 / 2 / 10 / 14 / 40 0 = off (HDR disabled)
2 = HDR on (not supported on some chips)
10 = single MEMC (common)
14 = TNR temporal noise reduction (chip-dependent)
40 = dual MEMC (chip-dependent)
Param 1-1Ignored; fill -1 as placeholder.
Param 2
Scene (bitfield)		 see below Combined per bit segments (8421 method):
• bit0~3 scene: 0 normal video · 2 normal game (recommended) · 3 eMV game 1 · 4 eMV game 2 · 5 short video · 6 allow eMV API
• bit4~7 latency: 0 OSD · 1 normal · 2 low · 3 ultra-low (lower latency = more artifacts)
• bit8~11 MEMC level: 0 level0
• bit12~15 N2M: 0 off · 1 on
Common values: 2=OSD · 18=normal-latency game · 34=low-latency game · 50=ultra-low-latency game
Param 3-1Ignored; fill -1 as placeholder.
Param 4
Game preset		 id Chip-internal game list id (see /odm/etc/iris_configs.xml). 255 = generic default preset — use it for games without a dedicated preset, otherwise mismatched resolution may silently disable effects.
Param 5
Source fps		 0 / 30 / 45 / 60 … The game's actual frame rate. Prefer an explicit value (e.g. 60) over 0 (auto) — explicit fps gives more stable insertion.
Param 6
Crosshair		 0 / 1 / 2 0 off · 1 PUBG Mobile crosshair · 2 PUBG Mobile holographic. Use 0 for other games.

Fixed formats at a glance:

Game (6 params):  258 6 10 -1 <latency> -1 <preset> <source fps>
Example:          258 6 40 -1 34 -1 3 60    (dual MEMC + low latency + Genshin preset + 60fps)
Video (3 params): 258 3 10 0 <0=off / 1=on>
Example:          258 3 10 0 1

The "off" section (clear commands)

The top-level "off" array in iris_config.json holds clear commands: sent before entering and on exiting MEMC to reset the chip. Do not delete it. Standard content:

"off": [
    "258 1 0",
    "267 2 3 0",
    "273 1 0"
]

Cautions

Never enable MEMC for IRX games! Games offering a built-in "display-chip 120fps" option (IRX render acceleration) + MEMC cause double processing: visual glitches and a huge power hit.
  • Parameters vary by chip (X7 PX8768 / X7 Gen 2 PX8778); when unsure check /odm/etc/iris_configs.xml and use the 255 generic preset for games without a dedicated one.
  • Fill Param 5 (source fps) with a real value; many systems lock games to 40/60fps then insert — use the actual running fps, not the target.
  • While MEMC is active the app locks the panel to 120Hz and temporarily takes over rate decisions (priority 70; user rules at 75 override); smart scheduling resumes on exit.
  • Video apps (Bilibili/Douyin etc.) use the 3-param form 258 3 10 0 x; games use the 6-param form. Mixing them may silently fail.
