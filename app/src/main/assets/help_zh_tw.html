OplusRefreshRate for PJA110 (一加 Ace 2 Pro) — App 版

應用程式是做什麼的

本應用程式接管面板更新率調度與 IRIS 獨顯晶片 (PixelWorks) 的顯示增強，包含三部分：

  • 更新率調度：智慧模式按場景投票決策（遊戲 120Hz、靜止 3 秒後降檔、觸控加速等），也可全域鎖定 60/90/120Hz。
  • MEMC 插幀（IRIS 獨顯）：按應用程式對晶片下發插幀 / 超解析度 / SDR2HDR 參數。進出時序對齊 ColorOS（清場 → ABYP → 鎖 120Hz → 切 PT → 寫參數），息屏或退出時一律回退 ABYP 旁路，防止切換風暴導致螢幕凍結。
  • 應用程式行為自訂：為每個應用程式單獨設定更新率模式與 MEMC 行為，使用者規則優先級最高。

快速上手

  1. 開啟「更新率模式」，選擇智慧模式或鎖定檔位。
  2. 要用 MEMC 插幀：先開啟「MEMC 插幀」總開關（預設關閉），再在「應用程式行為自訂」裡為目標應用程式選「強制開啟」，或在設定檔裡加套件名。
  3. 驗證：adb logcat -s ORR/Iris ORR/IrisExec ORR/PerApp ORR/Service ORR/Scene

檔案用途

應用程式外部目錄 app_rules.json無 root 權限寫入時的 fallback 位置，服務同樣會讀取。

iris 命令格式

每條命令對應一次 irisConfig 呼叫，格式為空格分參：

irisConfig <Type> <Param0> <Param1> ...

JSON 設定裡每條字串就是一條命令（不含 irisConfig 前綴），例如 "258 3 10 0 1"。未填寫的參數位置按 0 處理。同一應用程式的命令按順序依次下發。

Type 56 — 晶片模式開關（ABP 旁路）

控制獨顯晶片工作模式，是整個系統安全的核心。本應用自動管理，手動設定時請勿隨意下發。

參數值含義
0退出 ABP，晶片進入 PT（Pass-Through）工作模式 —— 插幀/超解析度生效的前提
1進入 ABP（Analog Bypass）類比旁路，晶片不處理畫面
16待機 ABP（Standby）
32睡眠 ABP（Sleep）—— 系統靜止時的預設安全態

讀取目前狀態用 irisConfig -getfeature 56（注意：-get 56 會區段錯誤，不要用）。sysfs 唯讀鏡像：/sys/kernel/iris/display_mode。

Type 258 — MEMC / HDR 主開關

插幀與 HDR 的總控，影片用 3 參數格式，遊戲用 6 參數格式。

位置取值含義
Param 0
模式		 0 / 2 / 10 / 14 / 40 0 = 關閉（停用 HDR）
2 = 啟用 HDR（部分晶片不支援）
10 = 單路 MEMC 插幀（單插，常用）
14 = TNR 時域降噪（部分晶片不支援）
40 = 雙路 MEMC 插幀（雙插，部分晶片不支援）
Param 1-1忽略位，填 -1 佔位。
Param 2
場景（位域）		 見下 按 bit 分段組合（8421 法拼接）：
• bit0~3 場景：0 普通影片 · 2 普通遊戲（推薦） · 3 eMV 遊戲模式1 · 4 eMV 遊戲模式2 · 5 短影片 · 6 允許 eMV API
• bit4~7 延遲檔：0 OSD · 1 普通延遲 · 2 低延遲 · 3 超低延遲（延遲越低畫面瑕疵越多）
• bit8~11 MEMC 級別：0 級別0
• bit12~15 N2M：0 停用 · 1 啟用
常用組合值：2=OSD 模式 · 18=普通延遲遊戲 · 34=低延遲遊戲 · 50=超低延遲遊戲
Param 3-1忽略位，填 -1 佔位。
Param 4
遊戲預設		 編號 晶片內部的遊戲清單編號（詳見 /odm/etc/iris_configs.xml）。255 = 通用預設預設，無獨立預設的遊戲一律填 255，否則可能因解析度不匹配不生效。
Param 5
原始幀率		 0 / 30 / 45 / 60 … 遊戲的原始幀率。建議填具體數值（如 60），不要填 0 讓晶片自動匹配 —— 明確幀率插幀效果更穩。
Param 6
準星輔助		 0 / 1 / 2 0 關閉 · 1 和平精英準星增強 · 2 和平精英全像。其他遊戲填 0。

固定格式速記：

遊戲（6 參數）: 258 6 10 -1 <延遲檔> -1 <預設> <原始幀率>
示例:         258 6 40 -1 34 -1 3 60    (雙插 + 低延遲 + 原神預設 + 60幀)
影片（3 參數）: 258 3 10 0 <0=關超分聯送 / 1=開>
示例:         258 3 10 0 1

off 段（關閉命令）

iris_config.json 頂層的 "off" 陣列是清場命令：每次進入 MEMC 前和退出時都會下發，確保晶片回到乾淨狀態。不可刪除，標準內容：

"off": [
    "258 1 0",
    "267 2 3 0",
    "273 1 0"
]

注意事項

IRX 遊戲不要開 MEMC！遊戲內提供「獨顯加速 120 幀」選項的遊戲（走 IRX 渲染加速）再疊加 MEMC 會雙重處理，畫面異常且功耗暴漲。
  • 晶片參數因型號而異（X7 PX8768 / X7 Gen 2 PX8778），不確定時以裝置 /odm/etc/iris_configs.xml 為準；無獨立預設的遊戲用 255 通用預設。
  • Param 5（原始幀率）盡量填具體值；很多系統會把遊戲鎖 40/60 幀再插幀，填遊戲實際執行幀率而非目標幀率。
  • MEMC 開啟期間本應用會鎖定面板 120Hz 並暫時接管更新率決策（優先級 70，使用者規則 75 可覆蓋），退出後恢復智慧調度。
  • 影片類應用（B 站 / 抖音等）用影片格式 258 3 10 0 x；遊戲類用 6 參數格式，格式混用可能不生效。

常見問題

現象排查
儲存規則提示寫入失敗正式路徑 /data/system/orr/ 需要 privileged 權限；ROM 內建安裝可寫，debug 安裝會自動 fallback 到應用程式外部目錄（功能不受影響）。
開啟 MEMC 應用程式沒反應① 總開關沒開；② logcat -s ORR/IrisExec 看 irisConfig 是否執行成功；③ 確認 /odm/bin/irisConfig 存在（不存在時 MEMC 自動停用並在日誌說明）。
插幀沒有效果核對命令格式（遊戲 6 參 / 影片 3 參）、預設編號、Param 5 原始幀率；用 irisConfig -getfeature 56 確認晶片是否切到 PT。
某些應用程式掉到 60Hz確認用智慧模式（靜止 3 秒才降檔是正常行為）；持續掉幀抓 logcat -s ORR/Scene ORR/Service 看投票結果。
螢幕凍結史（本機 known issue）本應用的回退邏輯保證任何異常路徑都回 ABYP。若手動玩 irisConfig 後出問題，執行 irisConfig 56 1 可立即回旁路。
